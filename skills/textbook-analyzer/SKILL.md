# 样本教材拆解（textbook-analyzer）

> 命令中的 `<SKILL_DIR>` 指本 skill 所在目录（如 `~/.claude/skills/unit-writer`）。skill 加载时的当前目录是用户项目根，不是 skill 目录，所以每条命令都必须带这个前缀。

## 适用场景

- 项目启动，需要从获奖教材中提炼体例规律。
- 手上有 3–5 套同学科同学段的教材，需要合成横向对比表。
- 已有分析表，需要补某一维度。

不适用：写正文（→ `unit-writer`）、设计大纲（→ `outline-designer`）、出版质量审校（→ `textbook-reviewer`）。

## 输入要求

| 输入 | 说明 | 缺失处理 |
|---|---|---|
| 教材文件 | PDF / 图片；**优先要目录页与 2–3 个正文样本页** | 必给 |
| 学科、学段 | 用于判断"合不合目标读者" | 必问 |
| 拆解维度 | 默认九个（见 `assets/分析表模板.md`）；用户可指定只拆某几个 | 用默认 |

**先探文本层再定方法**。教材 PDF 常见两类：带文本层的（可直接抽取）、扫描件（无文本层，抽取返回空）。判断方法：

```bash
python <SKILL_DIR>/scripts/render_pages.py <教材.pdf> --probe
```

输出 `text_layer: yes/no`。**是 no 就必须走渲染识读路线**，不要反复换抽取库浪费时间——扫描件换任何库都抽不出字。

## 执行步骤

1. **探测**。跑 `--probe`，记录页数与有无文本层。
2. **取目录**。渲染目录页（通常在前 15 页内），逐页识读，抄下「部分/章/节」标题与起始页码。
   命令：`python <SKILL_DIR>/scripts/render_pages.py <教材.pdf> --pages 12-20 --dpi 110`
3. **取正文样本**。按目录算出的章首页，渲染该章前 2–3 页。每套教材至少 2 个样本页，分属不同章。
4. **按九维填表**。逐维填 `assets/分析表模板.md`；每格必须带证据（页码或原文片段），无证据的格子留空并标「未采集」，**不要凭印象填空**。
5. **标定性/定量**。结构类（层级、章数、栏目顺序）为事实；语言类（句长、人称、术语密度）若未做统计，标【定性】。
6. **合成横向对比表**。多套教材逐维并列，最后一列写「共性 / 特色」。共性 ⇒ 后续写成强制规则；特色 ⇒ 写成可选风格。
7. **交未解决问题**。采集不到的部分单列一节，写明缺什么、需要谁补。

## 输出格式

```markdown
# 样本拆解报告

## 一、样本清单与采集状态
| 编号 | 教材 | 页数 | 采集方式 | 状态 |

## 二、单套分析表
### E1 <书名>（<版次>）
| 维度 | 内容 | 证据 |

## 三、横向对比表
| 维度 | E1 | E2 | E3 | 判定 |

## 四、提炼结论
### 共性（→ 强制规则）
### 特色（→ 可选风格）

## 五、未采集与待补
```

## 质量要求

- 九维全部有交代：填了就给证据，没填就写「未采集」+ 原因。**空白格视为不合格**。
- 页码可核对：每条结构结论要能指到具体页。
- 区分"这本书这么做"与"行业都这么做"：单套特征不写进共性列。
- 横向对比表只放同一维度的同类信息，不混入评价性描述。
- 涉及教材原文时只摘短句（≤30 字）作例证，不整段收录（版权要求，见 SOP 阶段 3）。

## 禁止事项

- 不得凭书名或印象推断内容；没看过的不写。
- 不得把"未采集"填成"无"——「无」是结论，「未采集」是缺口，二者含义不同。
- 不得引用整段原文，不得把样本教材的案例改写成自己的案例。
- 不得把扫描件的抽取失败当成"这本书没有文字"。
