# 整书修订（B 档）

> 适用：`textbook-polish` 的 B 档，作用域为**一本多章初稿**
> 来源：`mba-textbook-revision` 五阶段流程，按本系列架构重写并入
> 与 A 档（单件润色）的分工见 `SKILL.md`「两个档位」

## 零、B 档为什么存在，以及它凭什么放开手脚

A 档只有六种动作、不许改结构，是因为**改动幅度小，通用规则能兜住**——每处改动都能指到一个规则号，指不到就不改。这个机制在整本书上会失效：

- 全书的问题不是「哪句话不通」，而是「体系缺一块」「案例全是虚构的」「第 3 章和第 7 章对同一概念给了两个定义」。这些问题**没有规则号可指**，只能靠人判断。
- 修这些问题必然要重写、要调结构、要删改案例——超出六种动作的边界。

所以 B 档不是「放宽 A 档」，而是**换一套约束**：把「可枚举的规则」换成「实物化的标准」。具体做法是先精修一章做样板，把「这本书的合格线」变成一份看得见的终稿，再提炼成《全书编写与修改规范》，后续每一章都对着这份规范改、对着样板章比。

**代价必须说清**：B 档允许改结构、改案例、重写段落，因此**不再有 A 档「保真核对」那种兜底**——改写前后的内容差异是设计的一部分，不是错误。B 档防失控靠另外四道闸：四道关卡必停、不虚构、不改原意、一次一章。

## 一、启动：先确认项目信息，再建工作区

### 1.1 收集基础信息

能读到的不问；读不到的，**一次性**问完，未答复前不进阶段一：

- 教材名称
- 课程定位（核心课 / 选修课、学时）
- 目标读者（如：有 3–5 年工作经验的在职 MBA 学员）
- 章节总数与文件位置
- 特殊要求（出版社体例、字数上限、案例偏好，可为空）

**学段与范式不在问的范围内**——按 `SKILL.md` 第 1 步的判范式三问自行判定，写进工作区首页；判不出再问。

### 1.2 建 `_修订工作区/`

在项目文件夹下建 `_修订工作区/`，所有阶段产物只存这里。**每次开工先读进度表，不靠对话记忆**——这是 B 档能跨会话续做的唯一原因。

| 文件 | 内容 | 建立时机 |
|---|---|---|
| `00_进度表.md` | 每章所处阶段、终审轮次、得分、状态 | 启动时 |
| `01_全书诊断报告.md` | 阶段一产物 | 阶段一 |
| `02_样板章修改方案.md` / `02_样板章修改说明.md` | 阶段二产物 | 阶段二 |
| `03_全书编写与修改规范.md` | 阶段三产物，此后所有修改的唯一依据 | 阶段三 |
| `04_第N章_修改记录.md` | 每章的检查与修改记录 | 阶段四 |
| `05_第N章_终审报告_第K轮.md` | 每轮终审结果与退回单 | 阶段五 |
| `06_全书终审报告.md` | 全部章节通过后的全书验收 | 阶段五末 |

修订稿另存为新文件（`第N章_修订稿.md`），**不覆盖原稿**。

**与总控状态文件的接法**：项目根若已有 `textbook-builder` 的 `项目状态.md`，不另建第二套进度——在它的「进度流水」里追加一行指向 `_修订工作区/00_进度表.md`，把 B 档当作该项目的一个长环节对待。只有独立成书、没有项目状态文件时，`00_进度表.md` 才承担全量进度。

### 1.3 进度表格式

```
| 章 | 当前阶段 | 终审轮次 | 终审得分 | 状态 | 备注 |
|---|---|---|---|---|---|
| 1 | 阶段四 | 0 | - | 修改中 | |
| 2 | 阶段五 | 2 | 4.1 | 已退回 | 案例深度不足 |
```

状态只能取：`未开始` / `修改中` / `待终审` / `已退回` / `已通过` / `已上报用户`。**不许写「基本完成」「大致可以」**——这和 `textbook-builder` 对状态文件的要求是同一条。

## 二、B 档全程硬性规则

任何阶段都不得违反。前四条是 B 档自己的，后三条继承自 A 档。

1. **不虚构**：不编造案例、企业事实、数据、引文、文献。确需补充的写 `【待补充：需要什么材料，用于说明什么】`；原稿中疑似虚构的标 `【待核实：理由】`。这条同时是 `审校标准.md` 的 SJ-X4，触发即否决。
2. **不改原意**：保留原稿核心观点与知识点。要改观点、删知识点、调整章节归属，先向用户说明并取得同意。
3. **有证据**：每条问题判断注明章、节，必要时引原文短句。不凭整体印象下结论。
4. **可执行**：修改意见要具体到「怎么改」。**禁止只写「建议加强」「进一步完善」「可适当补充」**——这类话在 A 档的禁止事项里已有对应条目（说不出改法就不改），B 档同样适用。
5. **一次一章**：阶段四、五每次只处理一章，不得批量改写多章。
6. **以规范为准**：阶段三之后，所有修改与评审只依据《全书编写与修改规范》与样板章终稿。发现规范有缺陷，提修订建议由用户裁决，**不得自行偏离**。
7. **关卡必停**：【关卡】处必须停下等确认。用户明确说「不用等我确认」时才可连跑，且须在进度表备注写明。

## 三、阶段一：全书诊断（只诊断，不改正文）

以资深教材主编视角通读全部章节。诊断维度沿用 D1–D8，**但每一维都要落到本系列已有的判据上**——不能凭空造第二套评分口径。

| 编号 | 维度 | 检查重点 | 落到本系列哪 |
|---|---|---|---|
| D1 | 整体架构 | 章节顺序、知识体系完整性、缺失/重复/比重失衡 | 无对应（全书层，B 档独有） |
| D2 | 章内结构 | 学习目标、正文、案例、小结、思考题是否齐全，各章是否统一 | **体例符合度**（TY-06 ~ TY-11） |
| D3 | 逻辑论证 | 论点有无支撑、推理是否严密、概念先后顺序 | **科学性**（YY-33 / YY-34） |
| D4 | 深度与梯度 | 是否达到 MBA 层次（落到管理情境与决策，而非概念罗列）；全书难度是否递进 | **学段适切性**（`学段适配.md`） |
| D5 | 章节衔接 | 前后呼应、概念定义前后一致、有无重复定义 | 无对应（全书层，B 档独有） |
| D6 | 案例设计 | 真实性、中国商业情境、与理论的对应程度、有无疑似虚构 | **科学性**（SJ-X4 编造事实）+ 学段适切性 |
| D7 | 练习设计 | 层次（理解→应用→分析→决策）、能否支撑课堂讨论 | **练习质量**（`练习设计.md`） |
| D8 | 表达规范 | 术语、人称、语体、格式统一；AI 腔（空泛排比、套话、过度总结、「值得注意的是」「综上所述」） | **语言规范**（YY-31 ~ YY-39、§六 禁用词） |

**D1、D5 是全书层独有的两维，五维评分里没有它们**——因为 reviewer 一次只看一课，看不见章序与跨章定义冲突。这两维只做诊断、只提整章级建议，不并入五维分。

### 输出（写入 `01_全书诊断报告.md`）

1. **总体评价**（300 字内）：距离可出版水平的主要差距
2. **问题清单**，每条含：问题描述｜证据（章节 + 原文）｜影响范围（个别章 / 多数章 / 全书）｜修改方案｜优先级
   - P0：影响教材成立，必须先改（体系缺失、大面积虚构）
   - P1：显著影响质量
   - P2：打磨性问题
3. **各章评分表**：每章 × D2–D8，每项 1–5 分，附一句话主要问题
4. **待核实清单**：所有疑似虚构的案例、数据、引文——这张表最后要交到用户手上，不能被平均数吃掉
5. **全书性先决事项**：必须在样板章之前解决的（章节顺序调整、术语统一、体例确定）
6. **样板章推荐**：推荐 1 章并说明理由。标准：结构典型、问题覆盖面广、位置靠前、篇幅适中
7. **修改路线图**

### 【关卡 1】

向用户汇报：核心问题、P0 事项、推荐样板章。等用户确认样板章与全书先决事项的处理方式。

## 四、阶段二：样板章精修

样板章终稿是后续所有章节的质量基准，**标准要最高，且每处修改都要能总结成规则**——否则阶段三提炼不出东西。

### 4.1 修改方案（不动正文）

写入 `02_样板章修改方案.md`：本章问题清单（引诊断结论 + 细读新发现）；修改后结构大纲与原结构逐项对比并说明理由；案例与练习调整计划；需要用户提供材料或决策的事项。

### 【关卡 2】确认方案后才改写。

### 4.2 改写

按确认方案完成全章改写，遵守第二节全部硬性规则，并做到：

- **去 AI 腔**：删空泛排比、套话、重复小结，用具体论述和例子替代。手法沿用 A 档 B 层（`改稿动作.md` §四）——但 B 档允许连句子一起重写，不像 A 档只能做六种动作
- **MBA 层次**：概念讲清后，落到「管理者在什么情境下、如何用它做决策」
- **案例与理论一一对应**，讨论题能引出课堂争论

### 4.3 修改说明

写入 `02_样板章修改说明.md`，按「问题类型 → 修改手法 → 前后对比示例」整理，**至少覆盖 5 类主要修改**。这份说明是阶段三的原料，粒度参照 `示例-一段的完整轨迹.md`。

### 【关卡 3】

提交样板章修订稿请用户审阅。用户提意见的继续改，直到明确「定稿」。**未定稿不进阶段三。**

## 五、阶段三：提炼《全书编写与修改规范》

对比样板章初稿与终稿，结合用户审阅意见，写入 `03_全书编写与修改规范.md`。

### 规范必须包含八部分

1. **章节结构模板**：固定要素、顺序、各部分篇幅区间
2. **写作规范**：语体、人称、句式偏好、段落长度；禁用表达清单（附反例与正例）
3. **术语表**：统一译名、首现定义方式
4. **案例规范**：类型、长度、来源要求、与理论的对应方式、讨论题写法
5. **练习题规范**：题型、数量、难度分层
6. **质量检查清单**：20–30 条，每条都能用「是 / 否」判断。分两类：
   - **否决项（标 ★）**：任一不通过即终审不合格。至少含：无虚构；未擅改原意；章节结构符合模板；术语与术语表一致；无未标注的疑似虚构数据
   - **一般项**：其余可判断项
7. **评分细则**：D2–D8 各维 1–5 分的**打分锚点**（每个分值对应什么表现），并给出样板章终稿各维得分作基准分
8. **样板片段**：从终稿摘 3–5 段最能体现标准的段落

**每条规范都要能在样板章终稿里找到依据，不发明样板章没体现的要求。** 规范与通用 references 冲突时，本书规范优先——它更近、更具体；但涉及 SJ-X1 ~ SJ-X5 的底线，通用标准优先。

### 【关卡 4】确认规范后进阶段四。此后规范要改须经用户同意并记版本号（v1.0、v1.1…）。

## 六、阶段四：逐章对齐

一次一章，记录写入 `04_第N章_修改记录.md`：

1. **读依据**：重读规范（当前版本）与样板章终稿，**不凭记忆**
2. **对标检查**：对照质量检查清单逐项查原稿，列出不达标项
3. **列修改要点**：改什么、怎么改。涉及结构调整或改变原意时先停下问用户
4. **改写全章**：输出 `第N章_修订稿.md`
5. **自检**：对照清单逐项打勾；说明与样板章在结构、语体、案例写法上的一致性
6. **衔接检查**：列出与前后章需呼应或统一处
7. **更新进度表**：状态改 `待终审`

自检有未通过项的，继续改，**不得带着已知问题提交终审**。

> **这一阶段与 A 档的关系**：某章语言已达标、只差字句时，不必走全章改写，直接按 A 档四层改写处理即可，但判据以本书规范优先。B 档是容器，A 档是其中可调用的工具，不冲突。

## 七、阶段五：终审验收与退回

### 7.1 审稿人必须独立

避免「自己改、自己评」。

- **能调子代理时**：另起独立审稿代理执行终审，只给四份材料——规范、样板章终稿、本章修订稿、本章原稿。**不给修改记录和修改理由**，防止被修改思路带偏
- **不能调子代理时**：本会话内切换为审稿人立场，只依上述四份评审，并在报告开头注明「非独立审稿」

### 7.2 评审内容

1. **否决项检查**：逐项判断 ★ 项，给证据
2. **一般项检查**：逐项判断，算通过率
3. **维度评分**：D2–D8 按细则打分，每分附一句理由
4. **对标比较**：与样板章基准分逐维对比
5. **原意核对**：抽查原稿核心观点是否全部保留

### 7.3 通过标准（同时满足）

| 指标 | 门槛 |
|---|---|
| 否决项 | 全部通过 |
| 一般项通过率 | ≥ 90% |
| 各维度得分 | 每项 ≥ 4 分 |
| 维度平均分 | ≥ 样板章基准平均分 − 0.3 |
| 【待补充】【待核实】 | 允许存在，但必须全部列入清单交用户 |

用户可在启动时或规范中调整门槛，调整后以新门槛为准。

### 7.4 结果处理

**通过** → 状态 `已通过`，报告存档，进下一章。

**不通过** → 出**退回单**（写入当轮终审报告），状态 `已退回`，回阶段四第 3 步重改：

```
退回单｜第N章｜第K轮
不通过项：
1. [否决项/一般项/维度] 名称
   问题位置：X.X节，原文"……"
   问题说明：……
   修改要求：具体改成什么样（可引样板片段）
2. ……
本轮得分：D2=… D3=… … 平均=…（基准=…）
```

退回重改时：**只针对退回单列出的问题改**，不重写已达标部分（避免引入新问题）；改完再自检，然后提交新一轮终审；**新一轮终审要全量复查**，不能只看退回项。

### 7.5 退回上限

同一章**连续 3 轮**不通过，停止自动循环，状态 `已上报用户`，提交：三轮退回单汇总、反复不通过的根本原因判断（原稿基础太差 / 缺材料 / 规范本身不合理 / 门槛不合适）、建议处理办法（补材料、重写该章、修规范、调门槛）。由用户裁决后再走。

### 7.6 全书终审

全部章节 `已通过` 后做一次全书验收，写入 `06_全书终审报告.md`：

- 术语全书一致性（逐个核对术语表）
- 章节间引用与衔接是否正确
- 难度梯度是否递进
- 风格是否统一（随机抽不同章段落对比）
- 全书【待补充】【待核实】汇总清单

发现跨章问题的，把相关章退回阶段四处理，处理完复查。全书终审通过后提交交付说明：完成情况、各章终审得分、遗留待补充事项。

## 八、每次回复用户时

- 开头说明**当前阶段与章节**
- 到达关卡时明确说要确认什么
- 不汇报「感觉进步很大」这类不可核对的话
