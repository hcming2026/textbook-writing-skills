# 练习设计规范 v1.0

> 适用：管理科学与工程 · 本科高年级 / MBA
> 状态：v1.0 待学科专家审定

## 一、三层结构

每课练习分三层，比例约 **5:3:2**（本科高年级）/ **4:3:3**（MBA）。

| 层 | 目的 | 题型 | 认知层级 | 判定 |
|---|---|---|---|---|
| 基础 | 确认概念与机制被理解 | 名词解释、判断并说明理由、填空式推导 | 识记 / 理解 | 有标准答案，且答案可在正文找到依据 |
| 提高 | 确认能迁移到新情境 | 计算、案例分析、改错、流程重画 | 应用 / 分析 | 有参考答案，但需 2 步以上推理 |
| 拓展 | 确认能做判断与设计 | 方案设计、两难决策、小组调研 | 评价 / 创造 | 无唯一答案，须给评分要点 |

## 二、硬规则

| 编号 | 规则 | 判定方式 |
|---|---|---|
| LX-01 | 每道题必须标注对应学习目标 `LO-<单元>-<序号>`，无对应目标的题不得进入教材。 | 脚本 |
| LX-02 | 每课基础层 ≥3 题，提高层 ≥2 题，拓展层 ≥1 题。 | 脚本 |
| LX-03 | 三层题不得同质：不得把同一考点换个数字算三遍。 | 人工 |
| LX-04 | 计算题必须给全已知条件与单位，答案保留有效位数并说明取整规则。 | 脚本近似 |
| LX-05 | 案例分析题必须点名要用的分析工具（如「用五力模型」），不得只写「请分析」。 | 脚本查工具词 |
| LX-06 | 拓展题必须写明交付物形态（一页备忘 / 一张矩阵 / 5 分钟陈述），否则学生无法判断做到什么程度。 | 人工 |
| LX-07 | 每题给出参考答案或评分要点；拓展层给「合格 / 优秀」两级描述，不给标准答案。 | 脚本 |
| LX-08 | 题目中出现的组织、人物一律虚构化（同 YY-12）。 | 人工 |

## 三、题型配比建议（单课 8–12 题）

| 题型 | 本科高年级 | MBA |
|---|---|---|
| 概念辨析 | 3 | 2 |
| 计算 | 3 | 1 |
| 案例判断 | 2 | 3 |
| 改错/挑错 | 1 | 1 |
| 方案设计 | 1 | 2 |

## 四、参考格式

```
### 练习

**基础层**
1. [LO-2-1] 判断并说明理由：主数据与业务数据的主要区别在于数据量大小。（参考答案见附录 A）
2. ...

**提高层**
4. [LO-2-2] 某企业订单在 TPS 与 WMS 中的库存数相差 1200 件。请列出至少三条可能成因，并按排查成本从低到高排序。

**拓展层**
7. [LO-2-3] 为一家年营收 3 亿元的区域乳企设计三年信息化路线图。
   交付物：一页 A4 备忘（含现状、三步路线、每步的验收指标、最大风险）。
   评分要点：合格 = 路线与该企业规模匹配且给出验收指标；优秀 = 额外说明为何不选另两条路线。
```

## 五、常见不合格

| 不合格 | 问题 | 改法 |
|---|---|---|
| 「请谈谈你对信息系统的理解」 | 无对应 LO，无交付物，无法评分 | 指定 LO + 交付物 + 评分要点 |
| 「计算 EOQ」（未给需求率与订货成本） | 条件不全 | 补齐条件与单位 |
| 三道题都在算 EOQ（换数字） | 同质 | 改一道为「EOQ 假设不成立时怎么办」 |
| 拓展题「查阅资料写一篇小论文」 | 交付物模糊、无法验收 | 改为一页备忘 + 明确三个必答点 |
