# 体例规范 v1.1

> 适用：管理科学与工程 · 本科高年级 / MBA 中文教材
> 依据：阶段 2 横向对比（E1–E4）共性 + 项目级取舍；v1.1 的 TY-06 / TY-07 / TY-16 / TY-19 依据《信息管理学基础》（第三版）纵向通读（`docs/阶段2c-高质量教材写作范式.md`）
> 状态：v1.1 · TY-06 / TY-07 / TY-16 为修订条目，需学科专家抽章复核

## 一、结构与编号

| 编号 | 规则 | 判定方式 | 出处 |
|---|---|---|---|
| TY-01 | 层级不超过三级。第一级为「章」（含可选的「部分」层），第二级为「节」，第三级为「目」。超出三级的，拆为下一章。 | 脚本 | 共性（E1–E4） |
| TY-02 | 单册章数为 8–15 章。超过 15 章须设「部分」层归组，每组 3–5 章。 | 脚本 | E1/E3/E4 |
| TY-03 | 编号一律用阿拉伯数字，层级间用半角点号：`3` → `3.2` → `3.2.1`。不使用「第三章」「3.2 节」混写。 | 脚本 | E1/E2 实证 |
| TY-04 | 图表编号用三段式：`图 <章>.<节>.<序>`、`表 <章>.<节>.<序>`，如 `表 1.1.1`。全册连续，不按页重编。 | 脚本 | E2 实证 |
| TY-05 | 每章首节之前必须出现本章的引导段（≤400 字），说明本章要解决的管理问题与全章结构。 | 人工 | E3/E4 开篇案例的收敛替代 |

## 二、六栏体例（项目统一取值）

每节课固定六栏，顺序不得调整：`导语 → 正文 → 案例 → 思考 → 练习 → 拓展`。

| 编号 | 栏目 | 必含要素 | 字数（本科高年级 / MBA） | 判定方式 |
|---|---|---|---|---|
| TY-06 | 导语 | **四段推进**：① 铺背景——哪个条件变了（技术、制度、规模），要具体；② **反转出问题**——把好处翻成麻烦，E1 用「然而」，也可以用部门立场对立、方案互斥、投入与产出背离；③ 落任务——把麻烦转成这课要解决的一两件事；④ 给意义——解决它有什么用，落到决策后果上。末句提出本课核心问题。不出现定义与结论，不写「本课将介绍……」 | 150–250 / 200–350 | 脚本（④有问题句）+ 人工（①②③是否成立） |
| TY-07 | 正文 | 按「**概念 → 模式 → 机制 → 边界**」推进：先立「是什么、分几类、由什么构成」；再把**多个候选并列铺开**，各给来源与适用条件；然后回答「为什么是这个形状」（机制）；最后说明条件变了会怎样（边界 / 失效假设）。「模式」取何种形态见本条下方的说明。每节标题下 2 段以内必须出现一次具体所指（数据、流程、角色），不得连续抽象论述 | 3000–4500 / 2500–3500 | 脚本（所指密度）+ 人工（推进链是否完整） |
| TY-08 | 案例 | ① 决策者（有名有岗）；② 约束条件（时间、预算、权力）；③ 至少一处信息不对称或立场冲突；④ 结尾停在待决策点，不给结论 | 800–1200 / 1200–2000 | 人工 |
| TY-09 | 思考 | 3–5 问；至少 2 问属于 Bloom「分析」及以上；不得出现只需复述正文的问法 | 150–300 | 人工 |
| TY-10 | 练习 | 三层结构，比例约 5:3:2（基础:提高:拓展）；每题标注对应 LO | 见 `练习设计.md` | 脚本 |
| TY-11 | 拓展 | 1 项延伸阅读（含出处）+ 1 项实践任务（可团队完成） | 100–200 | 人工 |

> **TY-07 的「模式」取哪种形态**：理论型小节铺**前人模型**（提出者 + 年份 + 适用边界，即「人类已经想到过哪些答案」）；实务 / 决策型小节铺**备选路线或做法**（每条给主张者立场 + 成立条件）。
> 两者的硬要求相同——**不得只给一种就往下走**。只给一种，读者会把它当成唯一解，换个场景就不会用；这正是跳过「模式」这一步的实际代价。
> 参照 `skills/unit-writer/assets/范文-u2-l3.md`：该课属决策型，2.3.1 铺「一次性替换 / 分步替换 / 封装加中台」三条路线，即其「模式」段。

## 三、术语与引注

| 编号 | 规则 | 判定方式 | 出处 |
|---|---|---|---|
| TY-12 | 术语首次出现时给出中文全称 + 英文原文 + 一句话定义，三者齐全后再用简称。例：主数据（Master Data）：在多个业务系统间共享、需集中维护的核心实体数据。 | 脚本查英文括号 | E1/E3 |
| TY-13 | 引注用页下脚注，格式：`作者. 书名[M]. 出版地: 出版社, 年份.`；网络资源用 `作者. 标题[EB/OL]. (发布日期)[引用日期]. URL.` | 脚本 | E1 实证 |
| TY-14 | 每张图、每个表必须有来源：自制写「资料来源：作者绘制」，引用写「资料来源：<出处>, <年份>」。 | 脚本 | E2 实证 |
| TY-15 | 数据类陈述必须带口径：统计范围、时间区间、计算方式。三者缺一不得出现具体数值。 | 人工 | E2 实证 |

## 四、章末收口

| 编号 | 规则 | 判定方式 |
|---|---|---|
| TY-16 | 章末收口三项：① **本章内容提要**（≤600 字，连续散文、按节顺序分句串联，只归纳结论不复述论证）；② **本章重点**（编号 3–5 条，每条一个要点）；③ **复习与思考**（≥5 题）。 | 脚本（②③）+ 人工（①是否复述论证） |
| TY-17 | 章末列出关键术语表，术语必须在本章正文中出现过，数量 5–12 个。 | 脚本 |
| TY-18 | **字数口径**：本系列一律按「汉字数」计——只统计中日韩统一表意文字，不计标点、数字、英文字母与空格。与 Word「字符数（不计空格）」相差约 5%–8%，引用字数时须注明口径。 | 脚本 |
| TY-19 | 章末必须列 **本章参考文献**：≥8 条，格式同 TY-13，按正文引用顺序编号 `[1]`–`[n]`。所列文献必须在正文或脚注中被实际引用过，不得只列不用（凑书单）。 | 脚本（条数与格式）+ 人工（是否被引用） |

## 五、不合格写法对照

| 不合格 | 合格 | 违反 |
|---|---|---|
| 「本章介绍信息系统的相关内容」 | 「本章回答一个问题：为什么同一份数据在两个部门会得出相反结论」 | TY-05 |
| 导语写成「本课将介绍数据的分类，首先……然后……」 | 导语写成「企业上了十年的系统，数据却越理越乱。然而，真正的问题不是数据太少，而是同一个人在两个页面看到两个数字。要解决它，先得弄清数据究竟是怎么被组织起来的」 | TY-06 |
| 正文只有「概念→定义→方法」，跳过「前人给过哪些解释」 | 正文在给模型前先把三个经典模型并列铺开，各注提出者与适用条件，再解释它们为何形状不同 | TY-07 |
| 「信息是很有价值的东西」 | 「信息（Information）：经加工后能减少决策不确定性的数据。其价值随决策时点临近而衰减」 | TY-12 |
| 「如图所示的架构」 | 「如图 2.1.1 所示，订单在 TPS 层落库后，经 ETL 于 T+1 进入数据仓库」 | TY-04 / TY-14 |
| 「我国数据要素市场规模达到 1000 亿元」 | 「据《中国数据要素市场发展报告（2024）》，2023 年我国数据交易市场规模约 1000 亿元（口径：场内交易，不含场外撮合）」 | TY-15 |
| 案例结尾「由此可见，A 公司应当立即上线 ERP」 | 案例结尾「三个月后董事会要拍板。如果你是王厂长，你先动哪一块？」 | TY-08 |
