# 教材大纲设计（outline-designer）

## 适用场景

以下任一情形进入本 skill：

- 已有课程标准或培养方案，需要落成一本教材的章节目录。
- 已有零散的章节想法，需要整理成"单元—课"两级结构并配平课时。
- 已有旧版大纲，需要按新学段（如本科高年级 → MBA）重排难度与篇幅。
- 后续若要写某一课正文，但手上没有大纲——先回到本 skill，不要让 unit-writer 凭聊天记录猜结构。

不适用：单节课正文撰写（→ `unit-writer`）、习题设计（→ `exercise-designer`）、课标到学习目标的映射（→ `curriculum-mapper`）。

## 输入要求

必填三项，缺任一项先向用户询问，不要自行假设：

| 输入 | 说明 | 缺失时的处理 |
|---|---|---|
| 学科与学段 | 本系列默认「管理科学与工程」，学段只能是 `本科高年级` 或 `MBA` | 必问，学段决定全部篇幅与难度参数 |
| 学习目标 | `LO-<单元>-<序号>` 形式的清单，或可提炼出目标的课标条目 | 若只有课标原文，先提示用户走 `curriculum-mapper`；用户坚持时，按其原文提炼并在输出中标注【目标待 curriculum-mapper 复核】 |
| 课时规模 | 单册总学时 + 每周学时或周数 | 必问，用于配平单元与课 |

选填（有则用，无则按学段默认值，并在输出首行注明"按默认参数"）：

- 使用者：学生用书（默认）/ 教师用书
- 单元数量偏好、必须覆盖的重点章节、必须回避的案例行业
- 已有样本教材的体例偏好（栏目顺序、篇幅区间）

## 执行步骤

1. **确认参数**。读 `references/学段适配.md`（若尚未生成，按本文末"学段默认参数"执行），确定本学段的篇幅区间、案例复杂度、公式处理方式，把取值写进大纲 frontmatter 的 `params` 段，后续 unit-writer 直接继承。

2. **建立单元骨架**。把学习目标按"概念依赖顺序"聚类成单元，不按教材目录沿袭、不按章节数量均分。一个单元必须满足：内部目标共享同一决策情境族；单元数落在 6–8 之间；每单元 3–5 课。

   **单元之间要能串成一条链，不是一张主题清单。** 排完顺序，给每对相邻单元写一句「为什么 B 在 A 后面」——理由必须是概念依赖或任务进程（「第 5 单元讲排队，因为第 4 单元库存的 EOQ 不需要概率，排队才需要」），不能是「内容相关」。写不出理由的那一对，说明顺序是随意的，重排。
   > 参照：`信息管理学基础` 十章的顺序是一条任务链——信息产生（1 总论）→ 流动（2 交流）→ 分布（3）→ 获取（4）→ 整序（5 组织）→ 取用（6 检索）→ 给人用（7 服务）→ 系统承载（8）→ 谁来运营（9 机构）→ 什么规则（10 政策）。这条链本身就是该书的论证结构，不是目录。

3. **标注单元目标**。每个单元先写 3–6 条单元目标（`LO-<单元号>-<序号>`，认知层级按 Bloom 六级中文表述），单元目标必须是该单元所有课目标的并集上界——课目标不得出现单元目标里没有的能力项。

4. **拆课并配平课时**。每课围绕 1–2 条主目标，避免一课塞 4 条以上。按总学时配平：`Σ单元学时 = 总学时`，`Σ课学时 = 单元学时`，单课学时取 2 或 4（保证一次课能讲完）。

5. **填六栏配额**。每课固定六栏 `导语 / 正文 / 案例 / 思考 / 练习 / 拓展`，顺序不得调整。按学段默认参数给出导语与正文的字数区间；案例栏写明"案例方向"（给行业+冲突点，不写案例全文，案例全文交 `material-creator`）。

6. **留图位**。每课写 1–2 条图位说明，格式 `【图 <单元号>-<序号> 建议：<画什么>】`。只描述画什么，不描述配色与尺寸（插图不在本系列范围）。

7. **跑自检脚本**。执行 `python scripts/check_outline.py <大纲文件>`，按报出的 ERROR 逐条修正；WARN 项逐条判断，接受的在文件末尾"设计说明"里写一句理由。**脚本报 ERROR 时不得交付**。

8. **交付**。按"输出格式"输出，文件名按 `<course-slug>-outline.md`。在回复中给出：单元/课数量、学时配平结论、3 个需要学科专家拍板的判断点（例如"第 4 单元把排队论放在库存之前，因为它依赖的概率基础在单元 2"）。

## 输出格式

严格套用 `assets/outline-template.md` 的结构与标题写法，因为 `scripts/check_outline.py` 与下游 `unit-writer` 都按这套标记解析：

- YAML frontmatter：`course / discipline / level / edition / total_hours / units / textbook_mode / owner / params`
- 一级标题：`# <课程名> · 教材大纲`
- 单元标题：`## 单元 <N> <单元名>（<X> 学时）`
- 单元块内项目符号：`- 单元目标`（下挂 LO 条目）、`- 核心概念`、`- 前置要求`、`- 案例方向`
- 课标题：`### 第 <M> 课 <课名>（<Y> 学时）`
- 课块内必填项目符号：`- 学习目标`、`- 栏目`、`- 篇幅`、`- 核心知识点`、`- 前置知识`、`- 图位`

不得改动标题标记（`##`/`###`、`单元`/`第 X 课`、全角括号内的学时写法），下游靠它定位。

## 质量要求

- **课时必须配平**：单元学时之和等于总学时，课学时之和等于所属单元学时，不允许"大约"。
- **目标可追溯**：每条课目标都能回指一条单元目标；每个单元目标至少被一课引用（脚本会查孤儿目标）。
- **难度有落差**：同一单元内课与课之间难度递进，不得平行罗列四个同层级主题。
- **顺序有理由**：相邻单元之间能写出一句「为什么在后」，且理由是概念依赖或任务进程；理由只能是「内容相关」的，视为排序未成立。
- **MBA 与本科高年级参数必须显式不同**：若两版大纲除标题外文本雷同，视为未做学段适配。
- **篇幅给区间不给单值**，且区间跨度不超过 1.5 倍（`3000–4500 字` 合格，`1000–6000 字` 不合格）。
- 大纲中的案例方向必须原创或为公开通用情境，不得指向样本教材中的具体案例。

## 禁止事项

- 不得编造课标条目、学时规定、政策文件名；涉及具体规定时标注【待核实】。
- 不得为了凑单元数把同一目标拆成两课，也不得为凑课时把一课拆成两节。
- 不得输出"目录式一句话大纲"（只有标题没有目标/篇幅/栏目）——那不是本 skill 的合格产物。
- 不得引用或复述样本教材的目录结构；结构可以借鉴共性规律，文字必须自写。
- 不得跳过自检脚本，或脚本报 ERROR 仍交付。
