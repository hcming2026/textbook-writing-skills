# 案例检查单

交付前逐项核对，任一项不过不得交付。

## 结构四要素

- [ ] 有决策者：姓名 + 岗位 + 权责边界（他能决定什么、不能决定什么）
- [ ] 有硬约束：时间、资源、权力，至少两项写清具体数值或日期
- [ ] 有冲突：信息不对称 / 立场冲突 / 目标冲突，至少一处
- [ ] 停在待决策点：结尾是两难问题，不是结论

## 数据

- [ ] 总量 ≥ 分项之和
- [ ] 单位统一，且与该行业习惯一致
- [ ] 每个推算数字都能从给出的原始数字算出来
  - 例：吨均毛利 × 吨数 × 天数 = 停线损失，三者任缺其一即不成立
- [ ] 规模与行业常识相符（8 亿元营收的企业，不会只有 20 名员工）
- [ ] 自编数据已声明为教学虚构；公开数据已注明年份与出处

## 语言与合规

- [ ] 无真实在世个人姓名
- [ ] 真实企业仅用公开信息，且注明年份
- [ ] 未改写或拼接样本教材的案例
- [ ] 字数落在区间内（MBA 1200–2000 / 本科 800–1200）

## 教学可用性

- [ ] 案例内容能对上它声称服务的那条 LO
- [ ] 讨论问题至少 2 问属「分析」及以上层级
- [ ] 教师使用说明里写清了"这案例的坑在哪里"（学生容易误判的点）

## 常见不合格

| 现象 | 问题 | 改法 |
|---|---|---|
| "某公司决定上线新系统" | 无决策者、无约束 | 补岗位、补截止日期、补预算上限 |
| "各部门意见不统一" | 冲突抽象 | 写成两个具体岗位的具体分歧 |
| "由此可见，应选择方案 A" | 提前给结论 | 删结论，改成追问 |
| 数据算不通（分项和大于总量） | 硬伤 | 重算或删掉多余数据 |
| 案例 600 字就结束 | 篇幅不足 | 补情境细节与数据，不靠形容词 |
