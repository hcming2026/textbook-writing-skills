# 案例与素材编写（material-creator）

## 适用场景

- 大纲里只写了"案例方向"，需要落成完整案例。
- 正文需要一组可核算的情境数据（产量、成本、订单量）。
- 需要主题例题（含条件、求解、答案、边界）。

不适用：写正文（→ `unit-writer`）、拆解别人教材里的案例（→ `textbook-analyzer`，且不得改写复用）。

## 输入要求

| 输入 | 说明 | 缺失处理 |
|---|---|---|
| 案例方向 | 行业 + 冲突点（例：制造业 + 系统上线后车间仍用纸质工单） | 必给，否则会写成泛泛的成功故事 |
| 学段 | 决定案例长度与是否需要立场冲突 | 必问 |
| 服务的知识点 / LO | 案例必须能考到这条目标 | 必给 |
| 数据约束 | 企业规模、年份、是否可用真实公开数据 | 用默认（虚构化） |

## 执行步骤

1. **定决策者**。给一个有名有岗的人，写清他的权责边界。没有决策者的案例只能叫"例子"。
2. **定约束**。至少两项硬约束：时间（什么时候必须定）、资源（预算/人力）、权力（他能决定什么、不能决定什么）。
3. **造冲突**。至少一处信息不对称或立场冲突。两人意见一致的案例无法用于讨论。
4. **配数据**。给一组自洽的数字，且规模与行业常识相符。数据之间要能相互核算（总量 ≥ 分项之和）。
5. **停在待决策点**。结尾给两难问题，不给结论。给结论的案例等于提前交卷。案例正文同样是教材正文，语言限制见 `references/语言风格.md`（禁用词表、句长、人称），不存在「案例可以随便写」的例外。
6. **标来源**。自编写「本案例为教学目的虚构，企业与人名为化名」；引用公开数据写明年份与出处，不确定的标【待核实】。
7. **自检**。逐条核对 `assets/案例检查单.md`，尤其复核数据能否核算。
8. **交付**。输出 `<course-slug>-case-<编号>.md`，并在回复中说明这组数据背后的假设。

## 输出格式

```markdown
# 案例：<一句话冲突>

| 项 | 内容 |
|---|---|
| 服务目标 | LO-x-y |
| 学段 | MBA / 本科高年级 |
| 建议字数 | 1200–2000 / 800–1200 |
| 决策者 | 姓名 + 岗位 + 权责边界 |
| 硬约束 | 时间 / 资源 / 权力 |
| 冲突类型 | 信息不对称 / 立场冲突 / 目标冲突 |

## 情境
## 数据
## 待决策点
## 讨论问题（3–5 问）
## 使用说明（教师用）
```

## 质量要求

- 数据自洽可核算：给出的产量、单价、损失之间能对上；算不通的数据比没有数据更糟。
- 冲突具体：写"生产要保交付、IT 要保进度"，不写"各部门意见不一"。
- 场景可信：岗位叫法、审批流程、系统名称符合该行业实际，不出现"某部门经理张三决定采购 ERP"这类越权设定。
- 长度对得上：MBA 案例必须够 1200 字，靠细节而非形容词堆出来。
- 讨论问题指向分析层级，不是复述案例内容。

## 禁止事项

- 不得使用真实在世个人的姓名与可识别信息；真实企业只用公开信息并注明年份。
- 不得改写、拼接样本教材中的案例。
- 不得在案例正文里给结论或"正确答案"。
- 不得编造统计数字冒充真实数据；无法核实的一律标【待核实】并说明缺什么。
