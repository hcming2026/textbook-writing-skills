面向**管理科学与工程**学科（本科高年级 / MBA）的中文教材编写流水线。9 个 skill 把「拆样本 → 课标映射 → 大纲 → 正文 → 练习/素材 → 审校 → 排版」固化成一条可执行、可检查的流程：每一步都有确定的输入、确定的产物，以及一个能跑出结论的自检脚本。

写教材真正的麻烦不是「写不出来」，而是**写出来的东西不像一本教材**：篇幅凭感觉、练习和正文对不上、审校靠通读一遍说「感觉还行」。这套 skill 的做法是把这些判断变成可核对的事实——字数按区间卡、每题必须挂学习目标、审校先跑脚本再过人眼。

**不绑定某一个客户端。** 内容就是 Markdown 规则 + 纯 Python 脚本：遵循 [Agent Skills](https://skill.md) 开放标准的客户端（Claude Code、Cursor、Codex、WorkBuddy 等）可直接加载；不支持的客户端也能用——把仓库放进项目、在 `AGENTS.md` 里指个路即可；**完全不用 AI 也能跑**，四个校验脚本是零依赖的命令行工具。

**规则不是拍脑袋定的。** 68 条里的绝大多数能追到参考教材的具体页码；版式参数是用 300 dpi 渲染逐像素量出来的（版心 133.6 mm、每行 36 字、行距 1.65 倍），不是照抄 Word 默认值。拆解过程完整记在 `docs/` 里，**包括被推翻的判断和一处延续了四个版本的事实错误**——留错账是为了让后来的人看得出哪条规则改过、为什么改。

> ⚠️ **使用前请读第八节。** 本项目的规范库未经学科专家签字，人工盲评经项目负责人决定豁免。产出只能作内部起草，不得对外称「已审定教材」。

## 一、这套东西解决什么

三个具体的麻烦，不是三个卖点：

| 麻烦 | 通常怎么处理 | 这套东西怎么处理 |
| --- | --- | --- |
| 「第 3 课写了 1800 字，第 4 课写了 5200 字」 | 凭手感，或事后统一删改 | 大纲阶段就给每课篇幅区间，写完脚本实测；超区间直接报 ERROR |
| 「练习和正文对不上，考了没讲的内容」 | 出题时凭印象回忆正文 | 每题挂 `LO-x-y`，LO 来自课标映射；没有 LO 的题不进教材 |
| 「审校说『整体不错，但感觉有点空』」 | 意见无法复核，作者不知道改哪 | 每条意见必须给位置 + 违反的规则编号 + 可执行的改法；说不出位置的删掉 |

一句话：**把「像不像教材」这件事拆成能查的事实，剩下真正需要人判断的部分（观点对不对、案例真不真）单独标出来，不让它藏在平均分里。**

## 二、九个 skill

流水线的形状是固定的，上游产物是文件，下游直接读这个文件——**不要在对话里传结论**。整条链能中断、能重跑、能交给别人接着做，靠的就是这个约定。

```
0  textbook-builder ── 总控：读项目状态，判断你在第几步，路由到下面某一个
        │
        ├─ 1 拆解样本 ──── textbook-analyzer    样本 PDF → 九维分析表
        ├─ 2 课标映射 ──── curriculum-mapper    课标/培养方案 → LO 表 (.csv)
        ├─ 3 大纲 ──────── outline-designer     LO 表 → 三级大纲 (.md)
        ├─ 4 正文 ──────── unit-writer          大纲 + 节标识 → 六栏稿件 (.md)
        ├─ 5 练习 ──────── exercise-designer    稿件 + LO → 分层习题 (.md)
        ├─ 6 素材 ──────── material-creator     案例方向 → 情境数据 (.md)
        ├─ 7 审校 ──────── textbook-reviewer    稿件 → 审校报告 (.md)
        └─ 8 排版 ──────── textbook-formatter   通过稿 → .docx
```

### 0 `textbook-builder` — 判断你在第几步

说「我要写一本教材」或「下一步做什么」。它读 `项目状态.md`，判断当前处在 0–8 的哪一步，用三行讲清：现在第几步、这一步要什么输入、下一步做什么。**它不写作**，只做状态判断与路由。

> 进度以文件事实为准——产物存在、能过对应脚本、命名符合规则，三者齐才算完成。用户说「我写完了」不算。一次只推进一个环节；步骤固定 0–8 共九步，不得自创第 9 步。

### 1 `textbook-analyzer` — 把样本教材拆成可用的规律

先探文本层再定方法：有文字层直接抽取，是扫描件就走渲染识读。**扫描件换任何抽取库都抽不出字**，这一步判断错了会浪费很多时间。然后按九个维度填表，每一格都要带页码或原文片段作证据。

> 空白格视为不合格；**「未采集」不能填成「无」**——前者是缺口，后者是结论。摘原文不超过 30 字（版权）。「这本书这么做」不写进「行业都这么做」那一列。

### 2 `curriculum-mapper` — 课标落成可追溯的学习目标

把课标原文逐条抄下来（保留原条目号），一条对一条或多条映射成 `LO-<单元>-<序号>`，动词只从 Bloom 六级取。条数经验值：单册 6–8 单元时 LO 总数 30–48 条，超 60 条说明拆太细，低于 20 条说明太粗。

> 不许把「了解 / 熟悉 / 掌握」写进 LO 主干——不可测。课标原文照抄不改写；改写只发生在 LO 表述里。不得编造条目号或政策文件名。

### 3 `outline-designer` — 排结构，并给顺序一个理由

按概念依赖聚类成单元，不按目录沿袭、不按章节数均分。6–8 个单元、每单元 3–5 课，学时必须配平到分毫不差（`Σ单元学时 = 总学时`，`Σ课学时 = 单元学时`，不允许「大约」）。排完顺序后，**给每对相邻单元写一句「为什么 B 在 A 后面」**。

> 理由必须是概念依赖或任务进程（「第 5 单元讲排队，因为第 4 单元的 EOQ 不需要概率」），写成「内容相关」的视为排序未成立，重排。篇幅给区间且跨度不超过 1.5 倍。MBA 与本科版不得只差标题——那样等于没做学段适配。

### 4 `unit-writer` — 写一课完整正文

六栏固定：导语 / 正文 / 案例 / 思考 / 练习 / 拓展，顺序不可变。导语走四段式（铺背景 → 用「然而」把好处翻成麻烦 → 落成本课任务 → 说明有什么用），正文走「概念 → 模式 → 机制 → 边界」。

其中第二步「模式」有两个坑：只给一种就往下走（读者当成唯一解），或者给几种却写成清单（「常用方法有 A、B、C」，读者不知道为什么往下换）。**正确做法是接力**——后一个的出场理由来自前一个的缺点：缺点分条写实 → 外部条件变了 → 缺点尖锐化 → 「在这种背景下 B 产生」。

> 不碰六栏名称与顺序，不自创第七栏。不用「显然」「众所周知」跳过推理。术语首次出现给全称 + 英文 + 定义。脚本报 ERROR 不交付。

### 5 `exercise-designer` — 三层习题，每题挂目标

基础 / 提高 / 拓展三层，比例 5:3:2（本科）或 4:3:3（MBA）。拓展题**必须写明交付物形态**（一页备忘 / 一张矩阵 / 5 分钟陈述）和「合格 / 优秀」两级评分要点——否则老师看完不知道凭什么判合格。

> 只出一层不成立；「谈谈你的理解」这类无法评分的题不收；不出正文没覆盖的知识点。计算题给的条件要能被题目内部核算。

### 6 `material-creator` — 造案例与可核算的数据

四要素缺一不可：有名字有岗位的**决策者**（写清权责边界）、至少两项**硬约束**（时间 / 资源 / 权力）、一处**信息不对称或立场冲突**、结尾**停在待决策点**不给结论。

> 数据算不通比没有数据更糟——给的产量、单价、损失之间要对得上。不用真实在世个人的姓名；真实企业只用公开信息并注明年份。两人意见一致的案例无法用于讨论。

### 7 `textbook-reviewer` — 判能不能交，且不改稿

三步：先跑脚本收下全部事实性违规（**脚本结论不得手改**），再过五个否决项，最后五维打分。否决项触发任意一条，结论直接「不通过」、不给加权分——**给分会让否决被平均数稀释**。

> 每条意见必须能定位到原文，说不出位置的删掉这条。不代写片段（代写就变成改稿）。分数低于 4.0 不得判「通过」。不审自己写的稿。

### 8 `textbook-formatter` — 排成 Word，用实测版式

按排版映射表 v2 套样式：版心 14.6 cm、正文五号、固定行距 17 pt（约 1.65 倍）。合册排版时补章末三栏（内容提要 / 重点 / 参考文献）——这是**章级产物**，写课时覆盖不到，只能在这一环补。

> 不要改成 Word 预设的「1.5 倍行距」，那会让一面只装 900 字。排版阶段改一个字都得回 `unit-writer`。图位说明保留为占位文字，不能悄悄删。不生成 PDF。

**不适用**：纯翻译、润色、查重、逐字校对错别字、生成插图、生成 PDF、考试命题。

## 三、装上

Agent Skills 的约定是「一个 skill 一个目录，目录里必须有 `SKILL.md`」。不同客户端只是扫描的目录不同，**内容完全一样**，所以装一次可以喂给多个工具。

| 客户端         | 个人级（所有项目可用）            | 项目级（仅当前项目）                                                   |
| ----------- | ---------------------- | ------------------------------------------------------------ |
| Claude Code | `~/.claude/skills/`    | `.claude/skills/`                                            |
| Cursor      | 建议用项目级                 | `.cursor/skills/` 或 `.agents/skills/`（也会读 `.claude/skills/`） |
| Codex       | 建议用项目级                 | `.agents/skills/`                                            |
| WorkBuddy   | `~/.workbuddy/skills/` | `.workbuddy/skills/`                                         |

**推荐做法：只留一份真身，其余用链接。** 这套东西最大的维护坑是「规则副本不同步」——9 个 skill 各自带着 `references/` 副本，多装几份就等于多几个漂移点。

```bash
# 取一份真身
git clone https://github.com/hcming2026/textbook-writing-skills.git ~/src/textbook-skills

# 建个人级目录，把 9 个 skill 逐个链过去（macOS / Linux）
mkdir -p ~/.claude/skills
for d in ~/src/textbook-skills/skills/*/; do ln -sfn "$d" ~/.claude/skills/; done
```

Windows 用**目录联接**（实测：联接不需要管理员权限，符号链接需要，所以不要用 `ln -s` 代替）：

```powershell
$src = "C:\src\textbook-skills\skills"
Get-ChildItem $src -Directory | ForEach-Object {
  New-Item -ItemType Junction -Path "$env:USERPROFILE\.workbuddy\skills\$($_.Name)" -Target $_.FullName
}
```

> 不要用 `cmd` 的 `for /d %d in ("路径\*")`——给通配符集合加引号会关掉通配符展开，循环一个目录都拿不到；不加引号又扛不住路径里的空格。PowerShell 这版两种毛病都没有。

不想折腾链接就整目录拷贝，代价是以后改规则要重新拷、容易漏：

```bash
cp -r skills/* <目标目录>/
```

**客户端不认 `SKILL.md` 怎么办。** 内容照样能用，只是要手动指路。在项目根的 `AGENTS.md`（Cursor、Codex 都读；Claude Code 在没有 `CLAUDE.md` 时也读）里加三行：

```markdown
教材编写按 skills/textbook-builder/SKILL.md 的流程走。
各环节规则见 规范库/（68 条，TY/YY/XD/LX/SJ 编号）。
正文写完必须跑 skills/unit-writer/scripts/check_draft.py，有 ERROR 不得交付。
```

模型读到路径会自己去读文件，不需要把规则贴进上下文——这也是这套东西能跨客户端的原因：它依赖的是「文件可读」，不是「某个产品的功能」。

**验证装对了：**

```bash
# 把 $SKILLS 换成一个真实存在的 skill 目录
SKILLS=~/.claude/skills          # 或 ~/.workbuddy/skills
python $SKILLS/unit-writer/scripts/check_draft.py \
       $SKILLS/unit-writer/assets/范文-u2-l3.md
# 期望输出：结果：0 个 ERROR，0 个 WARN
```

跑出 `0 个 ERROR，0 个 WARN` 说明脚本与规则副本都齐了。若报「未识别到三层小标题」之类的结构错误，多半是文件没拷全；若报 `No such file`，检查链接是否指到了目录本身而不是目录内容。

**不用 AI 也能用。** 四个校验脚本只依赖 Python 标准库（3.8+，无第三方包），可以当普通命令行工具使：

```bash
python skills/unit-writer/scripts/check_draft.py 我的稿件.md
python skills/outline-designer/scripts/check_outline.py 我的大纲.md
python skills/curriculum-mapper/scripts/check_lo.py LO表.csv
python skills/exercise-designer/scripts/check_exercise.py 习题.md --level=MBA
```

唯一有外部依赖的是 `textbook-analyzer/scripts/render_pages.py`（扫版 PDF 需要 `pip install pymupdf` 才能渲染）。规则本身也是可读的：`规范库/` 里 68 条就是给人看的，不装任何工具、不看任何代码，照着写也行。

## 四、走一遍

不需要记 skill 名字，**照平常说话就行**，触发词命中后会自己路由：

| 你说                  | 谁接手                         |
| ------------------- | --------------------------- |
| 「我要写一本教材，从哪开始」      | `textbook-builder` 判断你处在哪一环 |
| 「拆解这本教材，做横向对比」      | `textbook-analyzer`         |
| 「把课标拆成学习目标」         | `curriculum-mapper`         |
| 「设计 48 学时 MBA 教材大纲」 | `outline-designer`          |
| 「按大纲写第 2 单元第 3 课」   | `unit-writer`               |
| 「给这一课配三层练习题」        | `exercise-designer`         |
| 「写个案例，制造业系统上线冲突」    | `material-creator`          |
| 「审一下这一课，看能不能交」      | `textbook-reviewer`         |
| 「按体例排版成 docx」       | `textbook-formatter`        |

下面是仓库里实际跑出来的输出，不是编的：

```bash
# 大纲合法性——结构不对就不该往下写正文
$ python skills/outline-designer/scripts/check_outline.py docs/测试用例/T-04-超长大纲.md
结果：0 个 ERROR，0 个 WARN

# 正文自检——通过稿（本仓库附带的范文）
$ python skills/unit-writer/scripts/check_draft.py skills/unit-writer/assets/范文-u2-l3.md
结果：0 个 ERROR，0 个 WARN
```

同一个脚本跑故意写坏的稿子（`docs/测试用例/T-06-问题稿.md`），报出来是这样的：

```
[ERROR] 导语 :: 41 字，超出区间 150–250（容差 ±20%）
[ERROR] 正文 :: 347 字，超出区间 3000–4500（容差 ±20%）
[ERROR] 案例 :: 61 字，超出区间 800–1200（容差 ±20%）
[ERROR] 练习 :: 2/2 道题未标注 LO，首条：1. 谈谈你对数据与信息的理解。…
[ERROR] 练习 :: 1 道题为不可评分题（LX-07），首条：1. 谈谈你对数据与信息的理解。…
[ERROR] 语言 :: 出现禁用词「赋能」×1（语言风格 六、禁用词表；总则 YY-01）
[ERROR] 语言 :: 出现禁用词「抓手」×1（语言风格 六、禁用词表；总则 YY-01）

结果：17 个 ERROR，4 个 WARN
```

注意它报的都是**能指到具体位置的事实**：第几栏、多少字、哪道题、哪个词。它不判「这段写得有没有价值」——那要人看，见第八节。

## 五、凭什么说这是教材的写法

拆了 4 本参考教材、通读了 9 个章节、量了 6 个版面之后，能把「好教材」压成一句可操作的判据：

> **拿掉这一段，读者会失去什么判断能力？**

失去的是知识，可以删；失去的是**判断**，就必须留或者补。教材不是知识的容器，是判断力的脚手架——知识点在别处都查得到，教材独有的是「什么时候该用哪个、为什么用它不用那个、用到什么边界为止」。

落到写法上有四件事，都是审校时抓得住的（详见 `docs/阶段2e-高质量教材的真谛.md`）：

| 抓什么 | 不合格的样子 | 合格的样子 |
| --- | --- | --- |
| **候选方法的出场理由** | 「此外还有 A、B、C」并列铺开，读者不知道为什么要讲这么多 | 第 N 个候选的理由来自第 N−1 个的**缺陷**（是接力，不是并列） |
| **结构有没有给成因** | 「信息系统由五部分组成」——只给清单 | 说清「为什么是这五个、为什么不是别的划分方式」 |
| **争议怎么收** | 两头都摆，读者不知道该信谁 | 争议 → 方法共识 → 现实证据 → 剩余分歧，最后落一个立场 |
| **多套框架怎么办** | 三个模型并列摆完就结束，留读者自己选 | 明确选定一套，并说明为什么选它、另外两套在什么条件下才用 |

版式同理，不是审美问题：36 字/行、1.65 倍行距、10.5 pt 五号，一个 250 字段落占 7 行，读者一眼扫完；压到 1.3 倍行距硬挤 1600 字/面，中文密得回行都串行。参数与量法见 `docs/阶段2f-排版图表与文字风格实测.md` 与 `skills/textbook-formatter/assets/排版映射表.md`。

**这些是判据，不是模板。** 换一个好作者用别的写法达成同一效果，规则不该误伤他——这是本项目验收每条规则的方式，也是修订记录里反复出现的那条教训。

## 六、三条硬约定

1. **学科与学段必给。** 学段只能是「本科高年级」或「MBA」，它决定全部篇幅参数——同一个知识点，本科导语 150–250 字、MBA 200–350 字；正文 3000–4500 对 2500–3500。学段说错，后面全错。
2. **大纲先行。** 写正文前必须有 `<slug>-outline.md`，或至少给清「课程名 + 单元号 + 课号 + `LO-x-y`」。没挂 LO 的稿件过不了审校。
3. **走文件不走口头。** 上一环的产物是磁盘上的文件，下游读文件，不读对话。

## 七、规则库

`规范库/` 是规则母本，共 **68 条**，用编号前缀区分来源：

| 文件        | 编号                | 条数 | 管什么                                       |
| --------- | ----------------- | -- | ----------------------------------------- |
| `体例规范.md` | `TY-01` … `TY-20` | 20 | 层级、编号、六栏体例、术语引注、章末收口、字数口径、章末参考文献、多框架选定 |
| `语言风格.md` | `YY-01` … `YY-30` | 30 | 判断依据原则；句式人称；段级推进（学术史／分域／收口／全景段／候选出场）；结构给成因、争议给共识；附 5 类禁用词表 |
| `学段适配.md` | `XD-01` … `XD-05` | 5  | 本科高年级 / MBA 的篇幅参数与难度曲线                    |
| `练习设计.md` | `LX-01` … `LX-08` | 8  | 三层结构、题型配比、可评分性                            |
| `审校标准.md` | `SJ-X1` … `SJ-X5` | 5  | 五维权重、否决项、脚本可判项清单                          |

**六栏体例**（顺序不可变）：导语 → 正文 → 案例 → 思考 → 练习 → 拓展。

**五个否决项**（触发即「不通过」，不进入评分）：思想性问题 / 科学性错误 / 版权问题 / 编造事实 / 违反 GB/T。设成否决项而不是扣分项，是为了避免用平均分把严重问题稀释掉。

**版式参数不在规范库里。** 版面归排版管，混进写作规则会让「写得对不对」和「排得好不好」互相干扰，所以单独放 `skills/textbook-formatter/assets/排版映射表.md`（v2，实测值）。它只约束排版环节，不参与审校评分——版式不对回排版，不是回改稿。

**两条红线**：脚本报 ERROR 不能交付；否决项触发不得判「通过」。WARN 可交付，但要在报告里写明接受了什么、为什么。

规则以**母本为准**，各 skill 的 `references/` 是副本。改规则必须双向同步，否则同一稿件在写作端和审校端判定会不一致。

### 未经第三方验证（豁免）

| 项目           | 状态    | 这意味着什么                      |
| ------------ | ----- | --------------------------- |
| 人工盲评（A/B 评分） | ⏭️ 豁免 | 「用了 skill 是否更好」**没有对照评分证据** |
| 规范库 5 份专家签字  | ⏭️ 豁免 | 「68 条规则是否正确」**只有编写者自证**     |

**豁免不等于通过。** 这两项是 SOP 要求的人工闸门，经项目负责人决定跳过。后果必须由使用者承担：

1. 产出只能作**内部起草**，不得对外称「已审定教材」。
2. 每份产出标注「初稿 · 未经学科审定」。

4. **事实与数据段落必须逐条人工核实。** 测试用例已经证明：脚本查不出编造事实，它只查格式与结构。

`docs/盲评包/` 完整保留（A/B 去标识文件、评分表、密封映射表），随时可以补做盲评。

## 十、常见问题

**Q：能不能直接写 MBA 的课，不给大纲？**  
不能。至少要给「课程名 + 单元号 + 课号 + `LO-x-y`」。没挂 LO 的稿件，审校第一步就会卡住——因为没有 LO 就无法判断这一课该讲什么、练习该考什么。

**Q：审校给了 4.5 分，是不是可以交了？**  
分数只反映**规范符合度**，不反映内容对错。五维评分里没有「观点是否正确」这一项，那是人工的事。另外见第八节第 3 条。

**Q：为什么脚本报了一堆 ERROR，我觉得没问题？**  
脚本判的是格式事实（字数、编号、栏目、挂载关系），不做语义判断。如果确实认为规则不合理，改 `规范库/` 母本并同步副本，而不是绕过脚本。

**Q：字数为什么和我 Word 里看到的不一样？**  
口径不同。本系列按**汉字数**计（只数中日韩统一表意文字，不含标点、数字、英文、空格），与 Word「字符数（不计空格）」相差 5%–8%，见 `TY-18`。

**Q：能改成别的学科吗？**  
`TY` 与 `YY` 两类规则通用；`XD`（学段参数）、`LX`（练习配比）和方法论部分是针对管理科学与工程的，换学科需要重做阶段 2 的样本拆解，不能只改几个数字。

**Q：为什么不直接生成 PDF？**  
当前工具链不支持，且排版环节只负责结构与样式（标题层级、栏目样式、图表题注、参考文献格式），封面、开本、色彩、装订属于印刷设计，不在范围内。交付 `.docx` 给出版社即可。
