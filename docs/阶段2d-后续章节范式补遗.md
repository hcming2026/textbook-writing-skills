## 零、先说结论：2c 有三处要改

读第 2、3、8 章，回改了 **3 条**规则。按要紧程度排：

| # | 原判断（v1.1.4 写入） | 改成 | 依据 |
|---|---|---|---|
| 1 | **TY-07**：多个候选**并列铺开** | **接力**——第 N 个的出场理由来自第 N−1 个的缺陷 | 本节、§四 |
| 2 | **TY-06**：导语**必须**走四段推进 | 硬项只有「管什么／不管什么／从哪个角度管」；四段式降为教学型首选，另列 2 种合法形态 | §一 |
| 3 | **TY-19**：参考文献**按正文引用顺序**编号；所列文献**必须被引用过** | 排序二选一（顺序编码制／著者音序）并全册统一；「必须被引用」改为「不得列入无关文献」 | §七 |

> 本文初稿只报了第 1 条，把另两条写在各节内部当"顺带修正"——读者只读结论段会以为只改了一条。2026-10-24 复核时补齐。

其中最要紧的是第 1 条：它把"清单"写成了"推理"。先展开这一条。

`阶段2c` 把「模式」这一步说成**并列铺开多个候选**。读完第 8 章才看清，E1 的做法是**接力**，不是并列：

> 结构化生命周期法的**缺点**（周期漫长、过程繁琐、要求用户一开始就说清需求）→ 20 世纪 80 年代**外部条件变了**（计算机技术与软件工具快速发展、企业要求更快更省）→ 这个缺点**日益尖锐** → 「**在这种背景下**，一种新的信息系统开发方法——原型法产生」→ 它**摒弃了**结构化方法那种一步步周密调查、严格分阶段、制作大量文档、最后才让用户看到结果的做法 → **换成了**先给可运行原型、与用户反复协商。

**每个候选之所以存在，理由由上一个候选的缺陷提供。** 「并列」会说成「有以下几种方法」，读者只知道清单；「接力」会说成「前一个为什么不够用」，读者知道**为什么需要下一个**。

这一条已回改 TY-07。下表是按节列出的全部支撑证据，其中 §一 与 §七 各自带出对 TY-06、TY-19 的回改。

## 一、章导语有三种范式，四段式只是其中一种

| 章 | 页 | 结构 | 范式 |
|---|---|---|---|
| 1 信息与信息管理 | 书 1 | 铺背景 →「然而」反转 → 落学科任务 → 给课程意义 | **问题驱动**（全书开篇专用） |
| 2 信息交流 | 书 43 | 立本体（交流是人类社会的基底）→ 交代研究范围（模式与特征、用户行为与心理、信息内容）→ 技术变化带来新课题 | **学科定位** |
| 8 信息系统 | 书 307 | 定义（数据密集型、人机交互的计算机应用系统）→ 定位（贯穿信息管理流程的技术支持）→ **本书取舍**（不只讲技术实现，更强调在组织信息管理与战略决策中的作用） | **定义 + 立场声明** |

三者共有的硬项只有一个：**在第一节之前把「这一章管什么、不管什么、从哪个角度管」说清**。

- Ch.8 的第③句是关键：「信息管理领域中的信息系统，在关注技术实现的同时，更强调……应用」——这句话在告诉读者「这本书和纯技术书不一样」。这是**立场声明**，比任何「本章介绍」都有用。
- 全章都没有「本章将介绍……」式预告。Ch.2 的「其研究主要集中在……」是**范围交代**，不是目录复述——它说的是这个领域在研究什么，不是本章有哪些节。

**对 TY-06 的影响**：四段式仍是教学型教材的首选（我们的读者需要被问题抓住才肯往下读），但不能写成「必须四段」，否则与样本冲突。改为「硬项 + 可选式」。

## 二、分类树：列完之后怎么往下走

书 44 页把「信息交流的几种形式」画成**大括号树形图**，不是编号列表：

```
信息交流 ┬ 自然信息交流 ┬ 非生物—非生物的信息交流
         │              └ 生物—非生物的信息交流
         ├ 人—自然的信息交流 ┬ 人—非生物的信息交流
         │                  └ 人—生物的信息交流
         └ 人—人的信息交流
```

三件事值得学：

1. **树给出全貌，正文按树的顺序逐支解读**——不是打乱讲。
2. **最后落到「把哪一支定为本学科对象」，并且用「为论述方便」收窄**：「从严格意义上讲，它应该被称为『社会信息交流』，为论述方便，我们直接将这种社会信息过程称为『信息交流』」。这一句解决了一个真问题：**分类列完之后，读者不知道你要讲哪一支**。
3. **分支顺序不是随意的**：自然 → 半自然 → 社会，复杂度与意识参与度递增，「最后一支」正是本学科对象，所以它落在最后一个而不是第一个。选分支顺序时要想清「按什么递进」。

## 三、「模型」型小节的四段模板（Ch.2, 书 49–51）

2.2 节导语只有一句话的作用：定义本节核心概念 + 交代价值 + 预告数量（「本节我们将介绍几种主要的信息交流模式」）。

每个模型固定四步：

| 步 | 内容 | 香农-维弗（书 49–50） |
|---|---|---|
| ① 来源 | 谁、哪年、在哪发表、**为解决什么问题** | 「1949 年，信息论创始人、美国数学家香农与维弗为**解决机器间信息互换**在当年的《通信的数学理论》中提出了著名的通信模型（如图 2-4 所示）」 |
| ② 结构 | 按环节走一遍，每环节一句功能 | 信源负责…编码器…信道…解码器…信宿…噪音… |
| ③ 贡献 | 定了什么、启发了谁 | 「为后来的许多交流传播过程模式奠定了基础，并引起人们对从技术角度进行信息交流研究的重视」 |
| ④ 局限 | 给 2–3 条**具体**的，不写「有局限性」 | 语义与语用层面关注较少；单向线性、没考虑「反馈」；对人类社会传播的解释能力有限 |

**①里多了一个 2c 没记的要素：目的。** 不只是「谁哪年哪刊」，还要「为解决什么问题」。这一项让模型与它要解决的问题绑定，读者才能判断它在什么场合还有效。

**④必须具体且分条。** 香农的局限给了三条，用「另外」连接，跨页写完。含糊的「存在一定局限性」在这里不成立——因为④是下一个模型的出场理由（见第零节）。

## 四、实务型小节的「方法三段式」（Ch.8, 书 333–334）

8.2.3 信息系统开发方法，单个方法的写法：

1. **别名**：「又称结构化开发方法，或者瀑布开发法」——先给读者可能听过的其他名字，不然读者以为遇到了新东西。
2. **诞生背景（在定义之前）**：先说「20 世纪 70 年代，信息系统开发过程中普遍存在着需求不清、步骤混乱和成功率低等问题」，再说「在这样的背景下，结构化生命周期法应运而生」。
   → 这是 YY-08「提出模型前先给没有模型时的困境」的**实证**，而且可以看出它比 YY-08 更进一层：**背景句要带年代与具体症状（需求不清、步骤混乱、成功率低）**，不能写「随着业务发展」。
3. **基本思想**：自顶向下、逐层分解，把复杂问题分成若干层次易于控制的子系统，直到能被有效定义的具体模块。
4. **优点**：分条（设计方法结构化 / 严格区分阶段 / 每阶段有明确任务 / 后阶段建立在前阶段上 / 避免盲目 / 成功率提高）。
5. **缺点**：分条，并且写到底（周期漫长 / 过程繁琐 / 不能预料变化 / 要求用户初期就说清需求 / **事实上**这几乎不可能 / 错误发现越早影响越小）。

**注意第 5 步的分量**：缺点段比优点段长，且带一个「事实上」的反驳。缺点写不实，下一个方法就出不来。

## 五、全景段：候选太多时怎么不全写

8.2.3 节导语在讲第一个方法之前，先用**一整段把整个方法家族点全名**：

> 「从工程技术角度分析，较有影响的方法有：结构化生命周期法、原型化方法、面向对象方法、CASE 方法等。测试驱动开发方法、行为驱动开发方法等基于敏捷开发思想的新型系统开发方法也开始发展……此外，还有分别适合于不同开发阶段的方法，如用于系统分析的软件需求工程法、形式描述法，用于系统设计的 HIPO 方法、Warnier-Orr 方法和 Jackson 方法……**这些开发方法是不断发展变化的，大多数情况下综合运用各种方法。**」

这一段干四件事：

1. **点全名**（8 个以上），让读者知道家族有多大
2. **给分类依据**（按工程技术角度 / 按敏捷思想 / 按所适用的开发阶段）
3. **声明「大多数情况下综合运用」**——防止读者以为要二选一
4. 然后**只展开其中 2–4 个**，其余不再提

这是解决「候选列不全」与「列全了写不完」这对矛盾的标准做法。2c 里没记这一手。

## 六、公式之后要接什么（Ch.3, 书 85）

3.1.3 马太效应的数学模拟，公式不是终点：

> 拉维昌德拉·劳 1987 年提出了累积优势分布的替代形式……即：`P(v) = (α+1)(1-v)^α`……**在实际应用中，人们常常感到计算 P(x) 而需要进行 q 和 β 的计算是很困难的。拉维昌德拉·劳将其改进为如下形式：** `P(x) = e^(-βq) - e^(-β(x+1))`……

**公式 → 这个公式怎么用 → 用起来有什么麻烦 → 谁改成了更好用的形式。** 只给公式不给「好不好用」，读者拿到了也用不出去。

这比现有的 YY-19（公式逐项释义）更进一步：YY-19 管「读得懂」，这一条管「用得上」。

顺带验证 YY-19 本身：8.1.1 的 `S = Σ S_i` 后面紧接「式中，S_i 为第 i 个子系统或要素，n 为……个数，S 为由 n 个子系统或要素组成的一个系统」——与 YY-19 完全一致，说明该规则不只适用于 E3。

### 一条必须纠正的事实

Ch.2 的参考文献 [1]–[21] **不按正文引用顺序排**，是按**著者音序**排（陈远 → 程妮 → 党跃武 → 方卿 → 丰成君 → 胡振华 → 贾晓彦 → 柯青 → 李国红 → 刘青端 → 钱建国 → 秦鸿霞 → 徐丽芳 → 岳泉，译著按国别标 [法][美] 插在其间）。

这与我在 v1.1.4 写进 TY-19 的「按正文引用顺序编号」**直接冲突**。GB/T 7714 本身有顺序编码制与著者-出版年制两套，教材常取「编号 + 著者音序」的折中——形式是顺序编码，排序按音序。**规则要允许这两种，并要求全册统一**，不能只认一种。

另外，TY-19 原写「所列文献必须在正文或脚注中被实际引用过」。这在「参考文献」这个名称下站不住：参考文献 = 编写时参考过的文献，本就允许有查过但未直接引用的。**改为「不得列入与本章主题无关的文献」**，这才是能判的标准。

## 八、章序本身就是一条教学逻辑（取自目录）

十章的顺序不是按研究对象分类，而是按**信息从产生到被管起来的过程**走：

```
1 信息与信息管理（总论）
2 信息交流   → 产生之后怎么流动
3 信息分布   → 流动之后呈现什么规律
4 信息获取   → 怎么找到它
5 信息组织   → 找到之后怎么整序
6 信息检索   → 整序之后怎么取用
7 信息服务   → 怎么提供给用户
8 信息系统   → 用什么系统承载
9 信息机构   → 谁来运营
10 信息政策与法律 → 受什么规则约束
```

这条链与书内 1.3.4「信息生命周期管理（ILM）」是同一个东西。**章序不是目录，是论证顺序。** 对 `outline-designer` 有直接用：单元排序要能说出「为什么这一章在那一章之前」，答不出就说明排序是随意的。
