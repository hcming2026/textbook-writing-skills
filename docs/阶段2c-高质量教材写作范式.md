## 一、章级结构

### 1.1 章导语：三种范式，四段式只是其中一种

测了三章导语，三种写法：

| 章 | 页 | 结构 | 范式 |
|---|---|---|---|
| 1 信息与信息管理 | 书 1 | 铺背景 →「然而」反转 → 落学科任务 → 给课程意义 | **问题驱动**（全书开篇专用） |
| 2 信息交流 | 书 43 | 立本体（交流是人类社会的基底）→ 交代研究范围（模式与特征、用户行为与心理、信息内容）→ 技术变化带来新课题 | **学科定位** |
| 8 信息系统 | 书 307 | 定义（数据密集型、人机交互的计算机应用系统）→ 定位（贯穿信息管理流程的技术支持）→ **本书取舍**（不只讲技术实现，更强调在组织信息管理与战略决策中的作用） | **定义 + 立场声明** |

三者共有的硬项只有一个：**在第一节之前把「这一章管什么、不管什么、从哪个角度管」说清**。

第 1 章的四段式展开如下（这是最完整的一种形态）：

| 位置 | 动作 | 例句（≤30 字摘录） |
|---|---|---|
| ① 铺背景 | 时代/技术条件已经变化 | 「随着当代信息技术的高度发展和广泛应用」 |
| ② 反转出问题 | 把好处翻成麻烦 | 「然而，信息量指数增长……又反过来危及人类的生存和进步」 |
| ③ 落学科任务 | 把问题转成学科要干的三件事 | 「需要我们进一步认识信息、研究信息、管理信息」 |
| ④ 给课程意义 | 说明为什么学这门课 | 「为开发信息和利用信息提供理论方法」 |

**② 有三种合法实现**：转折词（E1 用「然而」）／立场对立（两个部门各说各话）／场景反差（旧办法在新条件下失灵）。**不是必须出现「然而」两个字**——这一条 v1.1.4 就写错过一次，把字面连接词当成了动作。

这套写法的价值在于：**读者在读到第一个定义之前，已经知道这门学问为什么必须存在**。全段约 200 字，没有一句「本章介绍……」的预告式空话。

第 8 章的第③句是关键：「信息管理领域中的信息系统，在关注技术实现的同时，更强调……应用」——这句话在告诉读者「这本书和纯技术书不一样」。这是**立场声明**，比任何「本章介绍」都有用。

全章都没有「本章将介绍……」式预告。Ch.2 的「其研究主要集中在……」是**范围交代**，不是目录复述——它说的是这个领域在研究什么，不是本章有哪些节。

> **对 TY-06 的影响**：四段式仍是教学型教材的首选（我们的读者需要被问题抓住才肯往下读），但不能写成「必须四段」，否则与实测冲突。硬项 + 可选式。

### 1.2 章末三栏：内容提要 / 本章重点 / 本章参考文献

| 项 | Ch.1 实测 | Ch.2 实测 | 差别 |
|---|---|---|---|
| 内容提要 | ~200 字，按节序分号串联 | ~180 字，**开头回指上一章**（「在第 1 章导论章节之后，第 2 章对……进行了概观性的介绍」） | Ch.2 多了「承上」动作 |
| 本章重点 | 4 条；第 1 条带动词（「结合实际的应用领域，认识和理解……基本概念」），2–4 条纯名词短语 | 3 条；每条都是「名词短语 + 及其与……的比较」 | 句式**章内统一、跨章可不同**（与 YY-22 同理） |
| 参考文献 | [1]–[14]，GB/T 7714 | [1]–**[21]** | 条数随章长浮动；长章 21 条、短章 7 条（Ch.10） |
| 思考题 | 无 | 无 | **确认全书无习题是体例选择，不是第 1 章特例** |

内容提要用**一段散文**按节序串联，不是条目堆叠——这一点决定 TY-16 必须写「散文、按节序、分号串联」，不能只写「小结」。

**参考文献的排序是个坑。** Ch.2 的 [1]–[21] **不按正文引用顺序排**，是按**著者音序**排（陈远 → 程妮 → 党跃武 → 方卿 → 丰成君 → 胡振华 → 贾晓彦 → 柯青 → 李国红 → 刘青端 → 钱建国 → 秦鸿霞 → 徐丽芳 → 岳泉，译著按国别标 [法][美] 插在其间）。

这与 v1.1.4 写进 TY-19 的「按正文引用顺序编号」**直接冲突**。GB/T 7714 本身有顺序编码制与著者-出版年制两套，教材常取「编号 + 著者音序」的折中——形式是顺序编码，排序按音序。**规则要允许这两种，并要求全册统一**，不能只认一种。

另外，TY-19 原写「所列文献必须在正文或脚注中被实际引用过」。这在「参考文献」这个名称下站不住：参考文献 = 编写时参考过的文献，本就允许有查过但未直接引用的。**改为「不得列入与本章主题无关的文献」**，这才是能判的标准。

> **与我们体例的关系**：本项目的六栏体例（导语→正文→案例→思考→练习→拓展）是**教学型**教材的形态，与 E1 的专著型不是一回事。两类可以并存，但**不能混用**：一本教材里既放大量案例框又只写提要式收口，会显得两头不靠。可借鉴的是**推进逻辑**，不是栏目清单。

## 二、节级推进：概念 → 模式 → 机制 → 边界

### 2.1 四步各司其职

第 2 章的节顺序是判断范式的关键证据：

```
2.1 信息交流的基本概念   分类 / 含义与特征 / 行为 / 条件和要素
2.2 信息交流的模式       香农-维弗 / 拉斯韦尔 5W / 施拉姆 / 维克利 S-C-R / 米哈依洛夫
2.3 信息交流机制         社会信息流的形成 / 交流中的「栈」/ 直接交流与社会代理 / 传递模式
2.4 网络信息交流         兴起 / 模式及特点 / 移动 / 网络环境下的科学交流
```

四步各司其职：

1. **立概念**：先把「是什么、分几类、由什么要素构成」讲清，不急于给模型。
2. **列模式**：把学界已有的经典模型铺开，各给提出者与适用边界。这一步的作用是让读者知道「人类已经想到过哪些答案」，**而且要知道为什么需要下一个**。
3. **挖机制**：模式只描述形状，机制回答「为什么是这个形状」——社会信息流怎么形成、中间为什么需要「栈」（节点）。
4. **落到新情境**：网络出现后，前三个模型的哪些假设失效了。

第 3 章「信息分布」同构：马太效应（现象+负面影响+数学模拟）→ 离散分布规律（布拉德福德/齐夫/洛特卡/普赖斯）→ 生产者分布 → 时间分布（指数增长/逐渐过时）。**现象 → 规律 → 定律 → 变化**。

### 2.2 「模式」这一步：接力，不是并列

**这是最容易做错的一步，本文自己就错过一次。**

第一轮只读了第 1 章和目录，看到 2.2 下列着五个模型名，判断成「并列铺开」。第二轮读了 2.2 的正文（书 49–51）才发现，E1 写的是**接力**：

> 结构化生命周期法的**缺点**（周期漫长、过程繁琐、要求用户一开始就说清需求）→ 20 世纪 80 年代**外部条件变了**（计算机技术与软件工具快速发展，企业要求更快更省）→ 这个缺点**日益尖锐** → 「**在这种背景下**，一种新的信息系统开发方法——原型法产生」→ 它**摒弃了**结构化方法那种一步步周密调查、严格分阶段、制作大量文档、最后才让用户看到结果的做法 → **换成了**先给可运行原型、与用户反复协商。（书 333–334）

**每个候选之所以存在，理由由上一个候选的缺陷提供。**

| 写法 | 读者得到 |
|---|---|
| 并列：「常用的方法有 A、B、C。A 是……B 是……C 是……」 | 一张**清单**，不知道为什么要往下换 |
| 接力：讲完 A 的缺点 → 条件变了 → 缺点尖锐化 → 「在这种背景下」B 产生，它摒弃了 A 的做法 | 一条**推理**，知道每个候选解决的是谁留下的问题 |

> **这条错误的成因值得单独记**：判断是从**目录**推的。目录能告诉你"有哪些模型"，告诉不了你"怎么衔接"。凡涉及「怎么衔接、怎么递进、凭什么这样排」的判断，都必须读正文。

在接力这个前提下，三种小节形态各有模板。

**（一）理论型小节：模型四段模板**（Ch.2，书 49–51）

2.2 节导语只有一句话的作用：定义本节核心概念 + 交代价值 + 预告数量（「本节我们将介绍几种主要的信息交流模式」）。

每个模型固定四步：

| 步 | 内容 | 香农-维弗（书 49–50） |
|---|---|---|
| ① 来源 | 谁、哪年、在哪发表、**为解决什么问题** | 「1949 年，信息论创始人、美国数学家香农与维弗为**解决机器间信息互换**在当年的《通信的数学理论》中提出了著名的通信模型」 |
| ② 结构 | 按环节走一遍，每环节一句功能 | 信源→编码器→信道→解码器→信宿→噪音 |
| ③ 贡献 | 定了什么、启发了谁 | 「为后来的许多交流传播过程模式奠定了基础」 |
| ④ 局限 | 给 2–3 条**具体**的，不写「有局限性」 | 语义与语用层面关注较少；单向线性、没考虑「反馈」；对人类社会传播的解释能力有限 |

**① 里有一个容易漏的要素：目的。** 不只是「谁哪年哪刊」，还要「为解决什么问题」。这一项让模型与它要解决的问题绑定，读者才能判断它在什么场合还有效。

**④ 必须具体且分条。** 含糊的「存在一定局限性」在这里不成立——因为 ④ 就是下一个模型的出场理由。缺点写不实，下一个方法就出不来。

**（二）实务型小节：方法三段式**（Ch.8，书 333–334）

1. **别名**：「又称结构化开发方法，或者瀑布开发法」——先给读者可能听过的其他名字，不然读者以为遇到了新东西。
2. **诞生背景（在定义之前）**：先说「20 世纪 70 年代，信息系统开发过程中普遍存在着需求不清、步骤混乱和成功率低等问题」，再说「在这样的背景下，结构化生命周期法应运而生」。
3. **基本思想**：自顶向下、逐层分解，把复杂问题分成若干层次易于控制的子系统，直到能被有效定义的具体模块。
4. **优点**：分条（设计方法结构化 / 严格区分阶段 / 每阶段有明确任务 / 后阶段建立在前阶段上 / 避免盲目 / 成功率提高）。
5. **缺点**：分条，并且写到底（周期漫长 / 过程繁琐 / 不能预料变化 / 要求用户初期就说清需求 / **事实上**这几乎不可能 / 错误发现越早影响越小）。

**注意第 5 步的分量**：缺点段比优点段长，且带一个「事实上」的反驳。这正合接力——上一个的缺点就是下一个的出场理由。

**2 的「诞生背景」是 YY-08 的实证，且比 YY-08 更进一层：背景句要带年代与具体症状（需求不清、步骤混乱、成功率低），不能写「随着业务发展」。**

**（三）候选太多：全景段**（Ch.8，书 333）

8.2.3 节导语在讲第一个方法之前，先用**一整段把整个方法家族点全名**：

> 「从工程技术角度分析，较有影响的方法有：结构化生命周期法、原型化方法、面向对象方法、CASE 方法等。测试驱动开发方法、行为驱动开发方法等基于敏捷开发思想的新型系统开发方法也开始发展……此外，还有分别适合于不同开发阶段的方法……**这些开发方法是不断发展变化的，大多数情况下综合运用各种方法。**」

这一段干四件事：

1. **点全名**（8 个以上），让读者知道家族有多大
2. **给分类依据**（按工程技术角度 / 按敏捷思想 / 按所适用的开发阶段）
3. **声明「大多数情况下综合运用」**——防止读者以为要二选一
4. 然后**只展开其中 2–4 个**，其余不再提

这是解决「候选列不全」与「列全了写不完」这对矛盾的标准做法，落在 **YY-26**。

### 2.3 分类树：列完之后怎么往下走

书 44 页把「信息交流的几种形式」画成**大括号树形图**，不是编号列表：

```
信息交流 ┬ 自然信息交流 ┬ 非生物—非生物的信息交流
         │              └ 生物—非生物的信息交流
         ├ 人—自然的信息交流 ┬ 人—非生物的信息交流
         │                  └ 人—生物的信息交流
         └ 人—人的信息交流
```

三件事值得学：

1. **树给出全貌，正文按树的顺序逐支解读**——不是打乱讲。
2. **最后落到「把哪一支定为本学科对象」，并且用「为论述方便」收窄**：「从严格意义上讲，它应该被称为『社会信息交流』，为论述方便，我们直接将这种社会信息过程称为『信息交流』」。这一句解决了一个真问题：**分类列完之后，读者不知道你要讲哪一支**。
3. **分支顺序不是随意的**：自然 → 半自然 → 社会，复杂度与意识参与度递增，「最后一支」正是本学科对象，所以它落在最后一个而不是第一个。选分支顺序时要想清「按什么递进」。

### 2.4 公式之后要接什么（Ch.3，书 85）

3.1.3 马太效应的数学模拟，公式不是终点：

> 拉维昌德拉·劳 1987 年提出了累积优势分布的替代形式……即：`P(v) = (α+1)(1-v)^α`……**在实际应用中，人们常常感到计算 P(x) 而需要进行 q 和 β 的计算是很困难的。拉维昌德拉·劳将其改进为如下形式：** `P(x) = e^(-βq) - e^(-β(x+1))`……

**公式 → 这个公式怎么用 → 用起来有什么麻烦 → 谁改成了更好用的形式。** 只给公式不给「好不好用」，读者拿到了也用不出去。

这比 YY-19（公式逐项释义）更进一步：YY-19 管「读得懂」，这一条管「用得上」。

顺带验证 YY-19 本身：8.1.1 的 `S = Σ S_i` 后面紧接「式中，S_i 为第 i 个子系统或要素，n 为……个数」——与 YY-19 完全一致，说明该规则不只适用于一类内容。

### 2.5 可迁移的写法

写一节时先问四个问题，按序回答，就是一个完整的节：

> 它是什么（概念）→ 前人给过哪些解释（模式）→ 背后的机制是什么（机制）→ 条件变了会怎样（边界/新情境）

## 三、段级五种动作

### A. 定义阵列 + 目的交代 + 归纳

**先交代为什么要列一堆定义**，再列，列完再归纳——这是最关键的一步，缺了它读者会困惑于「为什么突然堆定义」。

> 「然而，对什么是信息迄今却尚未有公认的定义。这里，仅列举一些比较典型、比较有代表性的定义，以使读者对信息的概念有一个较为全面的认识：」（p1）
>
> 接着 20 条独立成行的短定义：「信息就是信息，既不是物质也不是能量。」「信息是事物之间的差异。」「信息是系统的复杂性。」……（p1–p2）

### B. 学术史叙事：人—年—刊—结论

缺二即不可核查。**没有年份的学术史，读者无从判断它是否还成立。**

### C. 分域扫描：段首定域 + 一例一文

每段开局点明是哪个域，段内一例一文。「各领域都重视 X」判不合格。判的是「有没有定域 + 有没有例证」，**不限定句式**（不要求非写成「在……领域」）。

### D. 对照表 + 表后机制解读

表后必须有解读段，且不复述数据（YY-17）。「要论证的进正文，能对照的进表」有两条路：

- 可对照（多指标 × 短定义）→ **表承担定义**（书 124 表 4-1，14 个指标的定义）
- 同一维度上的分类（类型 × 维度矩阵）→ **表承担结构**，正文按行展开（书 266 表 7-1）

### E. 收口句：由上可见 + 提炼共性 + 指出超越

> 「**由上可见**，在通信领域所展开的对信息的研究取得了丰硕的成果。在这里，信息被看做有序程度（或组织程度）的度量和负熵……这些**也是**香农、维纳、布里渊等人对信息的共同理解（哈特莱的信息定义仅仅是香农定义的特殊情形）。**这些认识比**仅仅把信息看做消息或通信的内容要丰富得多，深刻得多。」（p3）

三件套：**提炼这一组的共同点 → 指出组内谁覆盖谁 → 说明这一组比上一组多了什么**。

## 四、章序本身就是一条教学逻辑

十章的顺序不是按研究对象分类，而是按**信息从产生到被管起来的过程**走：

```
1  信息与信息管理（总论）
2  信息交流         → 产生之后怎么流动
3  信息分布         → 流动之后呈现什么规律
4  信息获取         → 怎么找到它
5  信息组织         → 找到之后怎么整序
6  信息检索         → 整序之后怎么取用
7  信息服务         → 怎么提供给用户
8  信息系统         → 用什么系统承载
9  信息机构         → 谁来运营
10 信息政策与法律    → 受什么规则约束
```

这条链与书内 1.3.4「信息生命周期管理（ILM）」是同一个东西。**章序不是目录，是论证顺序。** 对 `outline-designer` 有直接用：单元排序要能说出「为什么这一章在那一章之前」，答不出就说明排序是随意的。

1. **段落长度**：E1 段落普遍 180–280 字，比 YY-02 的 200 字上限长。这是专著型的舒缓节奏，教学型教材需要更短的段落供停顿与检索。**不改段限。**

4. **表编号「1-1」式**：改编号体例会连带改脚本正则，收益不抵风险。维持现状。

## 七、用自家范文反查规则（改完规则后做的对照）

规则写完不等于对。把 TY-06 / TY-07 的初稿拿去过一遍 `skills/unit-writer/assets/范文-u2-l3.md`（本系列自带的 0/0 范文），暴露出**两处过度具体**：

| 规则原措辞 | 范文实际怎么写的 | 问题 | 改法 |
|---|---|---|---|
| TY-06「用**「然而」**把好处翻成麻烦」 | 导语用「销售部门天天抱怨查不到库存，财务部门却坚持账实相符」——**部门立场对立**，没有「然而」 | 把字面连接词当成了动作，范文会因此被判不合格 | 改为「反转出问题」，三种实现：转折词／立场对立／场景反差 |
| TY-07「铺**前人模型**」 | 该课是决策型，铺的是「一次性替换 / 分步替换 / 封装加中台」三条**路线**，不是学术模型 | 把理论型小节的做法当成了通则 | 第一次改为「并列铺开多个候选」；**第二次（读第 8 章后）发现连"并列"也不对，最终改为接力**（见 §2.2） |

**教训**：从样本里提炼规则时，很容易把「这个样本用了什么」写成「必须用什么」。前者是字面，后者是动作。判据是——**换一个好作者用别的写法达成同一效果，这条规则会不会误伤他？** 会误伤，就说明规则还停在字面。

这条对后面所有从样本新增的规则都适用。YY-24 也已据此放宽：要求的是「段首定域 + 段内有例证」，不要求必须写成「在……领域」。

> 同一个坑踩了两次，方向相反：第一次把「必须有『然而』」当成通则（太字面），改成了"并列"；第二次把「并列」当成通则（用一章的写法覆盖所有情形），改成"接力"。**病根一样——用一章的写法去规定所有章。** 第二次能发现，是因为第二轮读了另外三章的正文。
